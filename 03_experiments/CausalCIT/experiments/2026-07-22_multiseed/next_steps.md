## 第一层：代码级修复验证（可直接动手，1-3天可见结果）

这些是基于已确认异常的针对性修复，每项都有明确的修改位置和预期效果。

### 1.1 降低先验权重 (prior_weight: 0.3 → 0.05)

**背景**: 诊断报告假设A——`channel_prior`（可学习先验）占门控的30%，淹没了基于数据的稳定性分数信号。这是 Full ≈ w/o EnvSplit 最可能的直接原因。

**修改位置**:
- `causal_channel.py:CausalStabilityGate.forward()` 第 111 行: `stability = stability * 0.7 + prior.unsqueeze(0) * 0.3` → 改为 `* 0.95 + ... * 0.05`
- `models_ablation.py:GlobalHSICGate.forward()` 第 147 行: 同上
- `models_ablation.py:CorrelationGate.forward()` 中类似位置

**实验设计**: 单seed快速诊断实验（合成数据+ETTh1 pl96），对比 prior=0.3 vs prior=0.05：
- 门控矩阵是否出现分化（非对角线元素不再全是 0.67）
- Full vs w/o EnvSplit MSE 差异是否拉开
- `channel_prior_sig` 的跨通道方差是否增大

**预期效果**: 如果先验权重降低后门控矩阵出现明显结构（如某些通道对 gate<0.3，某些>0.9），说明假设A成立，先验确实是问题根源。

---

### 1.2 增大 patch_num / 减少 n_envs（解决环境划分退化）

**背景**: 当前 `patch_num=12, n_envs=4` → 每环境仅3个patch，HSIC方差估计不稳定。

**方案A（推荐）**: `seq_len: 96 → 336`，让 `patch_num` 增大约3倍，保持 `n_envs=4`。
- 每个环境从 3 个 patch 变为 ~10 个 patch，CV估计稳定

**方案B**: 保持 `seq_len=96`，`n_envs: 4 → 2`。
- 每个环境从 3 个 patch 变为 6 个 patch

**修改位置**: `run_ablation.py` 中 `--n_envs` 参数，或 `run_multiseed.sh` 中直接传参

**实验设计**: 1个seed，合成数据，对比 n_envs=4 vs n_envs=2（或 seq_len=96 vs seq_len=336）：
- `stability_bias` 是否开始学习非零值
- 门控矩阵是否出现分化
- MSE 是否有改善

**预期效果**: 如果增大每环境样本量后门控质量提升，说明假设B成立，需要重新设计环境划分策略。

---

### 1.3 降低门控温度上限，增加选择性

**背景**: 当前 `temperature_param` 初始化为 1.0，`clamp(max=10.0)`。Full 最终温度收敛到 ~0.9，门控矩阵元素全部落在 0.66-0.67 区间——太"软"了，没有区分度。

**修改位置**: `causal_channel.py:CausalStabilityGate.__init__()` 中：
```python
self.temperature_param = nn.Parameter(torch.tensor(1.0))
```
改为初始化更小的值（如 0.3），或降低 clamp 上界（max: 10.0 → 5.0）。

**实验设计**: 单seed对比，温度初始化 1.0 vs 0.3 vs 0.1：
- 门控矩阵是否出现更陡峭的分布（有些值 >0.9，有些 <0.3）
- 门控熵的变化
- 对 MSE 的影响

**注意**: 温度只是"锐化" sigmoid，不会改变排序。真正的选择性需要稳定性分数本身有区分度（依赖 1.1 + 1.2）。

---

### 1.4 添加门控稀疏正则化

**背景**: 当前唯一的结构化约束是 gate_entropy（鼓励确定性），但缺乏**稀疏性**约束（鼓励某些通道对被关闭）。

**实现思路**: 在 loss 中加入 L1 正则化项：
```python
# 对非对角线元素施加 L1 惩罚，鼓励稀疏
off_diag_mask = 1 - torch.eye(n_vars, device=gate.device)
sparsity_loss = lambda_sparse * (gate * off_diag_mask).abs().mean()
total_loss = mse_loss + gate_entropy_loss + sparsity_loss
```

**修改位置**: `causal_channel.py:CausalChannelInteraction.forward()` 的 loss 返回处，或 `models_ablation.py` 的 trainer 中

**实验设计**: 单seed，对比 lambda_sparse=0 vs 0.01 vs 0.1：
- 门控矩阵中低值（gate<0.3）的比例
- 对 MSE 的影响

---

## 第二层：架构级改进（需要改模型，1-2周）

### 2.1 重构稳定性估计器

**问题**: 当前 `compute_stability_score` 的流程是：按时间顺序切分成 n 个环境 → 每个环境算 HSIC → 计算跨环境 CV → 作为稳定性分数。但：
1. HSIC 本身在 3 个 patch 的环境里噪音极大
2. CV 对小样本极敏感
3. 环境是**连续时间段切片**，没有独立同分布保证

**改进方向 A**: **Bootstrapping 环境划分**
- 不按连续时间切分，而是对 patch 序列做 bootstrap 重采样，构造多个伪环境
- 每个伪环境的 patch 数量 = patch_num（保证足够的统计量）
- 稳定性 = 多次 bootstrap 的 HSIC 方差的倒数

**改进方向 B**: **滑动窗口 HSIC + F-test**
- 对相邻时间窗口对计算 HSIC，用 F-test 检验跨窗口 HSIC 是否稳定
- p 值映射为稳定性分数（高 p = 稳定、应保留该通道交互）

**改进方向 C**: **基于注意力权重的一致性检验**
- 不依赖 HSIC，直接在注意力权重矩阵上做跨环境一致性检验
- 思路：如果通道 i→j 的注意力在 4 个环境里波动小（CV<阈值），保留该连接

---

### 2.2 引入结构化先验（因果图）

**问题**: 当前 `channel_prior` 是一个完全无约束的可学习矩阵 `[n_vars, n_vars]`，没有任何结构先验。如果真的想学到"因果图"，需要施加结构约束。

**改进方向 A**: **稀疏性 + DAG 约束**
- 对 `channel_prior` 施加 L1 正则化（稀疏），以及 NOTEARS 类的 DAG 约束（无环）

**改进方向 B**: **已知因果图的部分注入**
- 对于合成数据，因果图是已知的。把真实因果邻接矩阵作为先验注入
- 门控矩阵的初始化 = 真实因果图 + 小噪声
- 验证模型是否能在"已知真值"的情况下保持这个结构

**改进方向 C**: **低秩先验**
- 将 `channel_prior` 分解为低秩矩阵 `U @ V^T`，rank=1~2
- 减少参数量、增加归纳偏置

---

### 2.3 探索 Pearson 相关替代 HSIC

**背景**: w/o HSIC (Pearson相关) 在 ETTh1 pred_len=336 上 +2.04%，是所有变体中最好的。这可能不是偶然：
1. Pearson 是线性相关，在时间序列表征空间（高维非线性）中可能比 HSIC 更鲁棒
2. HSIC 的 RFF 核近似可能引入了额外噪声

**改进方向**:
- **Spearman 秩相关**: 非参数，对异常值更鲁棒
- **距离相关 (dCor)**: 能量距离的推广，能捕捉非线性依赖
- **互信息 (MI)**: 基于 kNN 的互信息估计
- 做一个"通道依赖度量对比实验"：在合成数据上（已知因果图），评估每种度量在"选择因果通道"这个任务上的 AUC

---

### 2.4 温度/门控的自适应机制

**问题**: 当前温度在整个训练过程中是固定初始值 + 可学习参数的策略，但门控的"确定性"应该与训练阶段相关：
- 早期：门控应该软一些（高温），不急于排除通道
- 后期：门控应该硬一些（低温），做出明确选择

**改进方向**: **退火式温度调度**
```python
temperature = max(initial_temp * (1 - epoch / total_epochs), min_temp)
```
或者用一个额外的 loss 项鼓励温度下降：
```python
temp_decay_loss = lambda_temp * temperature_param
```

---

### 2.5 集成 PatchTST 的预测结果做"安全网"

**背景**: 所有消融都显示 CausalCIT 最多打平 PatchTST，从未显著超越。一个务实的方向是：
- 同时跑 PatchTST + CausalCIT
- 用 CausalCIT 的门控诊断信息判断"当前样本是否适合通道交互"
- 如果 `gate_entropy > threshold`（说明门控不确定），fallback 到 PatchTST 的预测
- 类似 Mixture-of-Experts 的 gating 机制

这样可以把 CausalCIT 定位为一个**条件激活的增强模块**，而不要求它总是优于 PatchTST。

## 第三层：实验扩展（在修复生效后扩展验证范围）

### 3.1 更多真实数据集

当前只在 ETTh1 上验证。如果核心修复（第一层）在合成数据上生效，需要扩展到：
- **ETTm1 / ETTm2**: 15分钟级数据，不同时间粒度
- **Weather**: 21 个变量，更多通道 → 门控矩阵更大，因果选择的价值可能更显著
- **Electricity / Traffic**: 大规模多变量（300+ 通道），验证模型的可扩展性

关键问题是：**在多少个通道时，门控的"选择性"价值才会超过其计算开销？** 当前 7 通道下门控几乎无效，但 21 通道时可能不同。

---

### 3.2 OOD 鲁棒性重新测试

Demo 阶段 CausalCIT 最有说服力的结果是 OOD 场景下的鲁棒性（见 `experiments/2026-06-03_initial/demo/`）。
在门控修复后，需要在新模型上重新跑 OOD 实验。

实验设计：在合成数据上训练，在以下 OOD 条件下测试：
- 改变因果强度（增加/减少因果通道的依赖强度）
- 改变虚假相关性强度
- 改变噪声水平

---

### 3.3 长序列预测 (pred_len > 336)

w/o Gate 和 w/o HSIC 在 pred_len=336 上相对表现更好（vs pred_len=96 上全面为负），这暗示：**通道交互在长预测窗口更有价值，但门控机制在长预测窗口反而拖后腿**。

验证实验：在 ETTh1 上增加 pred_len=720 的测试点，对比各变体。

如果趋势确认（pred_len 越长，w/o Gate 越优于 Full），说明：当前门控对"长期依赖的通道交互"造成了过度压制。

## 第四层：理论分析和论文准备

### 4.1 "何时需要通道交互"的条件分析

这个问题比"怎么设计通道交互"更深层。收集以下维度的分析：
- **通道数量** vs PatchTST 优势（小通道数时 CI 足够，大通道数时需要 CD？）
- **预测长度** vs 通道交互价值（长预测更需要跨通道信息？）
- **数据特性**：通道间因果强度、虚假相关强度、信噪比

### 4.2 论文叙事调整

当前实验结果显示 CausalCIT ≈ PatchTST（不显著），这是一个需要面对的客观事实。

**选项A: 正面叙事（如果修复生效）**
- 将 "CausalCIT 在特定条件下优于 PatchTST" 作为主要贡献
- 定义"什么条件下需要因果通道交互"作为论文的差异化贡献

**选项B: 技术报告叙事（如果修复后仍不显著）**
- 不追求优于 PatchTST，而是做一篇深入的 ablation study 论文
- 核心贡献是"系统地分析通道交互在时间序列预测中的价值"
- 图1：通道交互的帮助 vs 伤害矩阵（条件×模型×效果）
- 图2：门控机制的局限性（门控矩阵热力图，展示其在不同场景下的退化）

### 4.3 实验记录规范化

将所有实验统一为以下格式，方便写论文时复用数据：

## 总结

当前最核心的三个问题，按"确定性问题→探索性问题"排序：

1. **确定性修复**: 先验权重过高 → 降低 prior_weight，大概率能解决门控未分化的问题
2. **结构性修复**: 环境划分信号太弱 → 增大 patch_num，或改 bootstrap 式环境划分
3. **探索性问题**: HSIC vs Pearson，通道交互的生效条件 → 需要更多对比实验和理论分析

建议先花 1-2 天做 P0（1.1 + 1.2），观察门控矩阵是否出现预期的结构性分化。如果 P0 结果正面，再规划 P1-P3 的详细实验矩阵。
