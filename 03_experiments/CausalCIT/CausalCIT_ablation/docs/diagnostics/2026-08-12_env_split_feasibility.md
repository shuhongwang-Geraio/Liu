# 语义环境切分可行性评估 (2026-08-12)

> 0 GPU 工作，数据驱动的前置判断。
> 脚本: `assess_env_split.py`（本目录）；数据均为项目已有:
> `01_external/TimeDRL/code/dataset/forecasting/ETT-small/ETTh1.csv` +
> `01_external/TimeDRL/code/dataset/forecasting/weather/weather.csv`。
> 关联: `2026-08-11_gate_static_diagnosis.md`（根因 3）、`do.md` 修 C 待办、想法 1 (DRO)。

## 1. 背景

门 1 静态诊断确认**根因 3**: `CausalStabilityGate` 的"环境"= 窗口内均匀切分
(`env_size = patch_num // n_envs`), 每环境仅 ~3 patch, 不反映真实机制变化 →
`cv≈0.005`, 跨环境稳定性项 `1/(1+cv)` 无信息 (log(hsic) 方差占比 100%)。

修 C 的候选方案是**语义环境切分**: 用时间戳 (季节 / 工作日vs周末 / 一天时段) 定义环境。
但此前无人验证语义环境切分在真实数据上是否真的比随机均分**更有信息** —— 本报告回答该问题。

## 2. 方法

- 对每个数据集, 保留 `date` 列, 解析出语义标签;
- 按标签分组, 组内计算通道相关矩阵 `R_e` (Pearson, 作为依赖强度代理);
- 度量"环境间相关矩阵差异" = 成对 Frobenius 距离均值, 归一化到每通道对 `|r_a − r_b|`;
- 对照: 当前方法 (时间行随机均分 n_envs 份) 的同类差异 (5 trials 平均);
- 判据: 语义组间差异 > 3× 随机均分 → 语义切分有信息, 修 C 可行。

## 3. 结果

| 数据集 | 语义方案 | #envs | 组间差异 | 随机均分对照 | 比值 |
|--------|---------|-------|---------|-------------|------|
| ETTh1 (7ch, 1h) | daynight 昼夜 | 2 | 0.0854 | 0.00626 | **13.7×** |
| ETTh1 | tod 时段(6h) | 4 | 0.0695 | 0.00626 | 11.1× |
| ETTh1 | season 季节 | 4 | 0.0666 | 0.00626 | 10.6× |
| ETTh1 | wd 工作日/周末 | 2 | 0.0076 | 0.00626 | 1.2× |
| weather (21ch, 10min) | season 季节 | 4 | 0.0198 | 0.00469 | **4.2×** |
| weather | tod 时段(6h) | 4 | 0.0168 | 0.00469 | 3.6× |
| weather | daynight 昼夜 | 2 | 0.0147 | 0.00469 | 3.1× |
| weather | wd 工作日/周末 | 2 | 0.0088 | 0.00469 | 1.9× |

## 4. 结论

1. **语义环境切分确实更有信息** (4–14× vs 随机均分) → **修 C 可行**。
2. **最佳语义方案因数据集而异**: ETTh1 昼夜最强 (13.7×); weather 季节最强 (4.2×)。
   通用建议: **季节 + 昼夜/时段**组合, 或按数据频率选择 (低频 → 昼夜/工作日, 高频 → 季节/时段)。
3. **工作日/周末 (wd) 几乎无信息** (1.2–1.9×): 单变量不足, 不应单独作为环境。
4. weather 的语义信号 (4×) 弱于 ETTh1 (14×): 修 C 在 weather 上的增益可能有限,
   且 weather 绝对差异 ~0.02 (相关元素平均差) 仍小 —— 预期 cv 从 ~0.005 提升但幅度有限,
   需实现后实测, 不可预先假设"修 C 一定带来显著收益"。

## 5. 未测数据集的外推判断

本机无 electricity/traffic (92M/131M, gitignore)。二者均有 `date` 列且格式与上述一致:
- **traffic** (862 通道, 1h): 交通流量有强日周期性/周末效应 → 语义切分应有信息 (推断 ≥ weather);
- **electricity** (321 通道, 15min): 用电模式季节/昼夜漂移强 → 语义切分应有信息 (推断 ≥ weather)。
建议在 GPU 服务器上用 `assess_env_split.py` 对二者补测 (脚本已支持任意路径)。

## 7. 备注

- weather 数据来自 TimeDRL 仓库 (2020-01 起), 与 PatchTST 标准版 (2010-2011) 时间范围不同,
  但均为 52696 行、10min 间隔; 方法结论不受年份影响。
- 本评估用 Pearson 相关矩阵作为依赖强度代理, 与门控实际用的 RFF-HSIC 是两套度量;
  语义切分对 RFF-HSIC 的信息增益需实现后验证 (预期同向)。
